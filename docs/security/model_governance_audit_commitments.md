# Institutional model governance audit commitments

The alert service writes an immutable business event and a `governance-event-commitment-v1` obligation in the same Mongo transaction. The commitment binds the event kind and content, institutional scope, actor, object, operation, proof digest, result, and time. The existing audit outbox later appends the commitment hash to the audit chain using a deterministic request ID. An acknowledgement lost after append is reconciled against that exact audit event. There is no distributed transaction with the audit authority or external witness.

Covered events include credential grant approval and revocation, emergency retirement request/authorization/consumption/revocation, trust-change request and review, policy governance decisions, publication, recovery, and reconciliation. Failed or rejected decisions are retained when their business service persists an immutable event. A pre-transaction validation failure has no committed business event to bind.

`GET /api/v1/governance/audit/commitments/{kind}/{eventId}` requires both `audit:read` and production governance authority. It returns digests and status, not credential material or full proofs. `PENDING`, `RETRYABLE`, and `BLOCKED` describe the outbox. `MISSING_EVIDENCE` and `TAMPERED` signal absent or inconsistent local material. `LOCAL_VERIFIED_EXTERNAL_UNCONFIRMED` means the business event, obligation, selected audit event, its direct predecessor, the current head, and its local anchor agree. It does not claim that every event between the selected event and the head was traversed: `chainRangeIntegrity` remains `NOT_CHECKED`. `LOCAL_VERIFIED_SIGNED_ENFORCED_WITNESS` additionally means the configured witness has enforced retention and the existing local audit authority validated its signature. `externalWitness` identifies this as local verification; `witnessVerificationAuthority` is `LOCAL_AUDIT_TRUST_AUTHORITY`, not an independent authority. The signing authority and key ID are returned when present. `currentAuthorization` remains `NOT_ASSESSED`. Historical WebAuthn proof verification is performed for reviewed grants and trust changes, with a separate proof-only endpoint for signed model-promotion reviews; `DIGEST_BOUND_NOT_REVERIFIED` explicitly marks event kinds whose original proof is not reverified.

`GET /api/v1/governance/audit/commitments/chain-ranges?start_position=N&end_position=M` verifies the inclusive range in the fixed `source_service:alert-service` partition. The service captures a stable head boundary and returns its position and hash. Later pages should pass both as `boundary_position` and `boundary_sha256`; the service rechecks that event and local anchor before and after scanning. A concurrent append beyond that boundary is reported separately and does not change the range being verified. Every returned `CHAIN_RANGE_VERIFIED` covers every requested event, its canonical hash, `previous_event_hash`, and exactly one matching local anchor, linked to a verified predecessor; `terminalEventSha256` identifies the verified end. Missing positions or anchors return `TRUNCATED`; inconsistent evidence returns `INVALID`. Requests larger than `AUDIT_CHAIN_RANGE_MAX_LENGTH` (default 1000, hard cap 10000) return `RANGE_TOO_LARGE`; no partial scan is ever reported as verified. The endpoint verifies local chain integrity only; it does not reverify action proofs or independently verify external witnesses.

`GET /api/v1/governance/audit/commitments/model-promotion-reviews/{proposalId}/proof` reuses the existing signed-review historical verifier. It returns only proof status and explicitly leaves event integrity, chain-range integrity, external witness, and current authorization unassessed. It never returns the retained assertion or private credential material. This proof-only result does not assert that a corresponding governance audit commitment exists.

Permanently exhausted obligations can be recovered only through the Security / Operations endpoint family by an actor
with the separate `model-policy:audit:recover` grant, audit-read authority, and production scope. Exact committed audit
events reconcile the acknowledgement without another append. A retry is available only when the original commitment
and complete bounded local chain prove the deterministic request ID absent. Each retry preserves the original identity
and historical attempt count, and the recovery budget is capped at three. Every operation stores an immutable hashed
receipt; recovery does not create a recursive audit obligation. Unknown, unavailable, or inconsistent evidence blocks
both controls.

| Threat | Detection and limit |
| --- | --- |
| Accidental event or outbox corruption | Commitment recomputation or missing-obligation result. |
| Application mutation of an existing event | Original chain receipt disagrees with the recomputed commitment. |
| Privileged Mongo edit, deletion, or partial rollback | Per-event reads detect missing records, broken links, replayed positions, and inconsistent local head/count. A coherent rollback of Mongo and all local records requires a separately retained witness to expose it. |
| Audit authority compromise | Signature verification alone cannot establish independence from the issuer. Rotate and retain trusted public keys; investigate affected attestations. |
| Mongo and audit authority compromise | Requires independent, retained witness material and an independent verifier with a pinned trust root. This stack does not claim that assurance. |

The local development stack generates the audit authority Ed25519 key once under ignored `deployment/.local/audit-trust-authority`. A one-shot loader copies it into a protected Docker volume for UID 10001; the authority mounts that volume read-only. Keep a protected backup of the local directory to verify historical signatures after host loss. Its storage and the local-file witness are not WORM, legal notarization, or an independent verifier. The audit API deliberately does not return an `EXTERNAL_INDEPENDENTLY_VERIFIED` conclusion from the issuing authority's own verification endpoint.
