# Policy publication recovery

Publication is performed only by the isolated publisher worker. The alert API can inspect and queue a bounded recovery; it does not possess the issuer private key or sign in an HTTP request.

| Durable state | Worker/operator behavior |
| --- | --- |
| `PENDING` | Worker atomically claims the original request. |
| `CLAIMED` | Live lease excludes other workers; an expired lease can be reclaimed. A crash leaves its attempt outcome explicitly uncertain. |
| `RETRYABLE` | Worker first classifies the original immutable commit; only proven absence permits another signing attempt. |
| `BLOCKED` | No worker claim. Proven absence with `ATTEMPTS_EXHAUSTED` permits a separately authorized retry, at most three times. An exact committed publication may be acknowledged without another signing allowance. Conflicts and unavailable evidence remain blocked. |
| `PUBLISHED` | Original job, immutable revision, signed policy and approval evidence remain linked. |

`GET /api/v1/governance/model-policies/{id}/publication/recovery` returns the original publication request ID, frozen draft SHA-256, job/proposal states, attempt/recovery/reconciliation counts, classified commit outcome, safe diagnostic, verified immutable receipt when available and bounded histories. The classifications are `COMMITTED_EXACT`, `NO_COMMIT_PROVEN`, `IMMUTABLE_CONFLICT`, `INCOMPLETE_OR_UNAVAILABLE_EVIDENCE` and `OUTCOME_UNKNOWN`. A failed Mongo read is `OUTCOME_UNKNOWN`, never proof of absence. `POST` at the same path accepts `{ "operationId": "unique-operator-command-id" }`: only `NO_COMMIT_PROVEN` with exhausted attempts grants one bounded new signing attempt. If the exact publication already committed, this request uses the reconciliation path and leaves the recovery budget unchanged. Other classifications fail closed.

`POST /api/v1/governance/model-policies/{id}/publication/recovery/reconcile` with the same operation body explicitly acknowledges an existing `COMMITTED_EXACT` publication. The service rechecks the original job, proposal, canonical content, full WebAuthn approval chain, publisher mandate at signing time and genuine Ed25519 issuer signature. A Mongo transaction fences the stale job, marks the original proposal and attempt, writes one `PUBLISH_POLICY` history event and one actor-bound reconciliation receipt. It changes no immutable policy or approval evidence, never signs and never resets attempt, recovery or reconciliation counters. Exact replay returns the verified result. A live worker lease, conflicting revision, partial evidence or unknown outcome cannot be acknowledged. The policy and retained approval evidence jointly form the immutable publication receipt; the job stores the same digest and publication time after acknowledgement.

All recovery routes require `model-policy:publication:recover`. A recovery operator must be distinct from the author, approver and original publication requester. Production additionally requires `model-policy:scope:production` and `model-policy:approve`; the backend enforces these independently of UI visibility. Local Keycloak fixture `policy-recovery` is for development only. Existing persisted realms require deliberate group/user provisioning.

Before signing, the worker rechecks the exact proposal, WebAuthn approval evidence, current actor/publisher/issuer mandates and issuer signing authority. Historical proof verification is distinct from permission to sign a new policy; later routine credential retirement does not erase a committed signature. Automatic lease reconciliation is capped at three claims by the durable Mongo predicate. If the final `BLOCKED` write fails, further automatic claims stop at that cap; the controlled operator path remains available after repair. A blocked job is never represented as published merely because a recovery request was accepted.

New signing recovery is unavailable for permanent conflict or invalid current trust. An exact historical commit can still be reconciled after routine credential retirement. Investigate immutable conflicts or unavailable proof; restore trusted configuration or resolve the incident through a separately reviewed new policy revision. Do not edit Mongo job status or reset attempt counters by hand. The attempt ledger has no TTL and should be retained with the policy evidence under the audit retention schedule.
