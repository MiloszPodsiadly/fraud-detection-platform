Status (2026-11-19): G02-A/G02-C, G03-A/B/C, G04-A/B, G05-A/B/C, and G06 GO inside the disabled, test-only scope; G02-B OPTIONAL BLOCKED for Merchant. No production Graph grant issuer, projection writer, or reader is wired. Final-head CI remains NOT VERIFIED.

## Scope and reading rule

This matrix evaluates only a private, disabled-by-default projection of exact source occurrences and owner-authenticated Device or Merchant facts. A source receipt, pseudonym, digest, scored ID, or private diagnostic result is not by itself a domain relation proof.

The narrow candidate is an occurrence-to-Device association inside one exact source scope. The owner-side bridge resolves a relation from retained source receipt lineage, Device integrity anchors, current Device and coverage grants, and the exact published INITIAL_RUN score. G05-A now persists and replays two independently signed occurrences through authenticated Graph Mongo, then reads both after reconstructing Graph, source, and Device adapters. The real-signer Mongo/Kafka vertical also rejects forged references, wrong epochs, revoked coverage, guessed owner IDs, an unrelated reader principal, and an overprivileged Mongo principal. It remains tagged UNTRUSTED_TEST_ONLY and makes no production trust claim (VerifiedDeviceAdmissionIntegrationTest.java:24-25; PrivateDeviceDiagnosticReaderIntegrationTest.java:245-345).

## G04-B current-authority and Graph snapshot fences

Every returned edge is resolved against current source receipt/RAW/ENRICHED lineage, Device observation and history anchor, coverage generation/watermark/current signer policy, pseudonym identity, and exact INITIAL_RUN score by the owner bridge. The reader compares the full ordered Graph candidate rows before owner checks, after the first owner pass, and after a second owner pass, then rechecks its Graph grant. Any unavailable or changed evidence fails closed with no edges. Empty Graph results remain `UNAVAILABLE/COVERAGE_UNAVAILABLE`; no owner currently provides sealed completeness for a `NOT_PRESENT_IN_BOUNDED_VIEW` or `VERIFIED_EMPTY` result.

G04-B focused validation passed 55 tests with 0 failures/errors and 1 conditionally skipped benchmark. The exact command and the race-by-race test table are in `docs/adr/graph_evidence_projection_boundary.md`. Tests include real Testcontainers source receipt deletion, history anchor deletion, lower coverage watermark, pseudonym-key rotation, current coverage revocation between owner passes, and a Graph lifecycle mutation during the Mongo read. Owner/Graph/source databases still do not share an atomic snapshot; no compactor or TTL worker exists, so compaction is N/A and retention remains unapproved.

## G05-A signed vertical and request deadline semantics

`PrivateDeviceDiagnosticReaderIntegrationTest.deviceGraphBridgeRevalidatesSignedOwnerEvidenceAndExactInitialScoreAfterRestart` now writes two separate owner-issued Device relations to authenticated Mongo Graph, verifies exact replay returns `EXISTING`, closes the writer, reconstructs the Graph reader and fresh source/Device owner adapters, then reads one exact edge from each signed occurrence. The two rows share the same authorized scoped Device node and have distinct canonical relation IDs. Reads take place at `NOW + 6s`, beyond the five-second admission operation deadline, demonstrating that transient operation timeouts do not truncate persisted owner evidence validity. The request deadline still bounds each admission/write, and replay does not extend the row's original `validUntil`.

Focused final outcomes: `GraphEvidenceAdmissionTest` 10/10, `MongoGraphProjectionStoreIntegrationTest` 14/14, and the signed source/Device/Kafka/Graph vertical 1/1. Tested images were MongoDB `7.0` and Kafka `3.8.0` on Windows 11, Java 21, Docker Desktop 29.5.2. The detailed exact commands and limitations are in the ADR. This was adapter reconstruction within one test process; it is not a process restart or production runtime evidence.
