# Signed model-promotion reviews

Production model-promotion APPROVE and REJECT reviews use the existing institutional passkey verifier. The browser obtains a challenge from `POST /api/v1/governance/model-promotion/proposals/{proposalId}/reviews/challenges` using the usual review fields (`approvalId`, `outcome`, `operationId`, `rationale`, `rationaleSha256`). It confirms the WebAuthn assertion and submits `{ "intent": <same review fields>, "challengeId": "...", "responseJson": "..." }` to `POST /reviews/signed`. The old `POST /reviews` remains for non-production scopes but rejects normal production reviews without a signed proof.

The challenge is domain-separated from policy decisions and binds the trusted OIDC issuer/subject, operation and proposal IDs, exact model name/version/feature contract/artifact SHA-256, institutional scope, environment, intended use, source and requested target state, expected and current lifecycle revision, proposal/assessment/policy SHA-256, decision, rationale SHA-256, nonce and expiry. Neither `acceptedAt` nor the later commit timestamp is represented as signed by the authenticator. Both are assigned server-side. The shared Yubico verifier enforces exact RP origin, UV, one-time challenge, owner and counter. Its evidence, counter update, model review, accepted decision, receipt and local audit participate in the same Mongo transaction. A retry with the identical signed assertion recovers the original review; changed actor, intent or assertion fails closed.

Maker/checker separation, current mandate and production scope, fresh policy/evidence and lifecycle revision are still checked by the existing workflow. A model-promotion decision never authorizes deployment by itself. Existing production callers using the unsigned review endpoint must migrate to the two-step OIDC+WebAuthn flow and register a protected passkey first.

Emergency retirement has a narrow unsigned exception: an independent reviewer with both production `model-promotion:approve` and `model-promotion:retire` mandates must use rationale `BREAK_GLASS:<case-id>:<reason>` (case ID 6–64 safe characters; reason at least 20 characters). The review carries a distinct `BREAK_GLASS_RETIRE_MODEL_PROMOTION_PROPOSAL` local audit action. It cannot approve a non-retirement target or use a generic rationale. This exception is for safety-critical retirement only.
